Salesforce Inspector Native

Sixteen admin and developer tools in one Lightning app. You install it as plain Salesforce metadata, so there's no browser extension, Data Loader or local install to get approved.

Chapters

Why it exists

On many corporate laptops you can't install Data Loader or a browser extension like Salesforce Inspector Reloaded. That might be IT policy, missing admin rights, or an extension allowlist. This app gives you the same kind of tools inside Salesforce.

Nothing to install locally

It deploys like any other metadata. You open it from the App Launcher, and all calls go to your org's own domain.

Respects your access

Every tool runs as you, with your object, field and sharing access. The permission set only opens the app. It grants no data access.

Review before it writes

Tools that change things stage the change first. Nothing is written until you click Save, Apply or Deploy.

Install

Try it in a sandbox or Developer Edition org first. You need the Salesforce CLI.

  1. Deploy the metadata

    git clone https://github.com/ilchec/salesforce-inspector-native.git
cd salesforce-inspector-native
sf org login web --alias myorg
sf project deploy start --target-org myorg

  2. Assign the permission set

    Setup → Permission Sets → Salesforce Inspector Native → Manage Assignments → Add Assignment. Or from the CLI:

    sf org assign permset --name Salesforce_Inspector_Native --target-org myorg

  3. Open the app

    In the App Launcher, search for Salesforce Inspector Native. Tools are grouped into Data, Schema, Users & Security and Org Info in the left-hand menu.

The tools, and how to use them

Each card says what the tool is for, gives the steps, and has a link to that part of the video. Read-only tools never change your org. Writes tools change it, but only when you confirm.

Data

Records in and out

Create Records

Writes

Create or upsert many records at once in a grid.

  1. Pick an Object, then a Layout: Default Layout, a record type, All Fields or Required Only.
  2. Add rows: Paste from Excel, Import CSV, or Add Row and type.
  3. Check the column mapping. Matching headers map automatically. Map the rest with the dropdowns, or drag a column onto a field.
  4. To update existing records instead of creating duplicates, tick Match key (or use Match Fields) on a unique field.
  5. Click Save and choose Partial success or All or nothing. The results link to every saved record.

Download CSV Template gives you a file with the right headers for the chosen layout.

Query Records

Writes

Run SOQL, then work with the results in place.

  1. Type a query, for example SELECT Id, Name, Owner.Name FROM Account, and click Execute Query.
  2. Results open read-only. Click Edit to change values, then Save. Each edited row updates its own record.
  3. Export CSV downloads the grid as it is now, including unsaved edits.
  4. To delete, tick rows and click Delete Selected, then confirm.

Parent fields such as Account.Owner.Name show as read-only columns. Child subqueries aren't supported. Results are capped at 200 rows, so use Data Export for more.

Data Export

Read-only

Download a full CSV of an object without writing SOQL.

  1. Pick an Object. Every field starts selected, so move out the ones you don't need.
  2. Optionally set Max rows. Otherwise the export runs until the object runs out, up to 50,000 rows.
  3. Click Export CSV. The file downloads in your browser.

Values are raw rather than locale-formatted, so the file can go straight back into Create Records.

Data Masking

Writes

Replace personal data with fake values, for example before giving a sandbox to a vendor.

  1. Pick an Object and move the text, email and phone fields to mask into Fields to mask.
  2. Optionally add filters (Equals, or Contains for text) so only matching records are masked. Multiple filters are ANDed.
  3. Click Preview Masking to see the replacement values. Nothing is written yet.
  4. Click Apply Masking. You get a result for each record.

Up to 200 records per run. Only fields you can update are offered.

Schema

Objects, fields and metadata

Schema Explorer

Read-only

See every field on an object in one table.

  1. Pick an Object.
  2. Type in Search fields to filter by label or API name.
  3. Click a row's pencil icon to open that field in Setup.

The columns show type, what a lookup references, required, unique, external ID, createable and updateable.

Relationship Map

Read-only

See how objects connect.

  1. Pick an Object. On the left is what it looks up to. On the right is what looks up to it.
  2. Click any node to re-center the map on that object.
  3. Each column shows 25 at a time. Use Show More for the rest.

Field Creator

Writes

Create several custom fields in one go.

  1. Pick an Object. In each row, enter a Label (the API name fills in) and choose a Type.
  2. Options shows only the settings for that type: length, precision, picklist values, help text, required, unique and so on.
  3. Permissions sets Read/Edit per permission set. Apply to All Fields copies it to every row.
  4. Use the copy icon to clone a row, or Add Row for more. Then click Deploy Fields.

Needs Customize Application. Lookup and Master-Detail aren't supported.

Picklist Manager

Writes

Maintain a custom picklist's values without going through Setup.

  1. Pick an Object and a Picklist field. Active and inactive values are both listed.
  2. Type a value and click Add Value. Use the arrows to reorder.
  3. Toggle Active to deactivate a value, or edit the Label to rename it.
  4. Click Save, or Discard to undo everything.

Renaming changes only the label, so existing records keep their value. The API can't delete values, so deactivate them instead. Needs Customize Application.

Impact Analysis

Read-only

Find what uses a custom field or object before you change it.

  1. Pick an Object and a Custom field, or turn on Whole object.
  2. Click Analyze. References are grouped by type: flows, Apex, layouts, formula fields, validation rules and more.

Uses Salesforce's Dependency API, which doesn't include Reports and is capped at 2,000 references. An empty result means nothing was found. It doesn't guarantee nothing depends on the field.

Translation Finder

Read-only

Find where a piece of UI text comes from, so you know what to translate.

  1. Type at least two characters of the text you see.
  2. Matches are grouped into Custom Label, Object, Field (label or help text) and Picklist Value.
  3. Each result links to the right place to add the translation.

Results are capped at 100. In orgs with many managed packages, a search can take a few seconds.

Users & Security

Who can do what

Permissions and Groups

Writes

Assign access to many users at once.

  1. Search and tick the permission sets, permission set groups or public groups to assign. The Type filter narrows the list.
  2. Click Next: Select Users, then search by name, username or email and tick the users.
  3. Optionally set an Expiration Date (permission sets and groups only), then click Assign.

You get one result row per user and item. Re-assigning updates the expiry date instead of failing.

FLS Matrix

Writes

Edit field-level security for many permission sets at once.

  1. Pick an Object, then Select Permission Sets to choose which ones appear as columns.
  2. Tick or clear R/E per field. The top row sets object access (Read, Create, Edit, Delete, View All, Modify All).
  3. Click Save Changes. Clearing a box removes that access.

The same dependency rules as Setup apply. For example, Edit implies Read. Needs Customize Application to save.

Org Chart

Read-only

Browse the manager hierarchy.

  1. It opens on you, with your manager on the left and your direct reports on the right.
  2. Click anyone to re-center on them, or use Jump to a user to search.

Record Access Inspector

Read-only

Check what a user can do with one record.

  1. Paste a Record Id and search for a User.
  2. Click Check Access to see Read, Edit, Delete and Transfer, plus the max access level.

You need to see the record yourself. A "no access" result can also mean the record isn't visible to you.

User Comparison

Read-only

Find out why two users get different results.

  1. Pick User A and User B.
  2. Compare settings, profile and role, permission sets, permission set groups, public groups and queues.
  3. Only differences show by default, highlighted. Turn on Show All to see everything.

Org Info

Capacity at a glance

Limits and Licenses

Read-only

See how close the org is to its limits.

  1. Limits shows every org limit as a gauge, highest usage first.
  2. Licenses shows user and permission set license usage as used / total.
  3. Click Refresh to reload.

Tab Settings

Admin

Show only the tools your team needs.

  1. Each tool has a Salesforce Inspector Native Tab custom metadata record.
  2. Clear Is Enabled to hide a tool. The change applies the next time the app loads, with no redeploy.
  3. Open in Setup on the Tab Settings page goes straight to those records.

Permissions

The bundled permission set opens the app and its Apex classes. It grants no object or field access, so each tool works only with what the user can already reach. A few tools also need a system permission.

ToolAlso needs
Field Creator, Picklist Manager, FLS Matrix (saving)Customize Application. Salesforce requires it for any schema change.
Permissions and GroupsAssign Permission Sets for permission sets and groups. Manage Public Groups for public groups.
Query RecordsNothing extra. It allows general-purpose SOQL, so assign it as carefully as you would Data Loader or Workbench.
All other toolsNothing extra.

FAQ

Does it send data anywhere outside Salesforce?

No. It's Lightning components and Apex running in your org. The tools that use the Tooling API call your org's own domain. There are no external scripts, CDNs or third-party endpoints.

Do I need a Remote Site Setting, Named Credential or Connected App?

No. The Tooling API calls go to the org's own domain, which needs no extra setup.

Is it a managed package?

No. It's unpackaged source you deploy with the Salesforce CLI. Everything uses the InspectorNative prefix, so it won't clash with your own components.

How do I remove it?

Delete the components with sf project delete source --source-dir main --target-org myorg. Fields, values and permissions you changed with the tools stay as they are.
